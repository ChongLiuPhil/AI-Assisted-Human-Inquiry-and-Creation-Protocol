## 1. ICMJE — 作者身份、最终批准与问责

**主要来源：** International Committee of Medical Journal Editors，*Defining the Role of Authors and Contributors*。

https://www.icmje.org/recommendations/browse/roles-and-responsibilities/defining-the-role-of-authors-and-contributors.html

**2026-09-17 重新核验。**

### 已核验主张

ICMJE 当前的 authorship criteria 包括：

- 对研究构想/设计或数据获取/分析/解释作出实质贡献；
- 起草或对重要思想内容进行批判性审阅；
- **最终批准待发表版本**；
- 同意对工作的所有方面承担问责，包括与准确性或完整性有关的问题得到适当调查与解决。

ICMJE 还说明，应披露 AI 辅助技术的使用，并且作者仍对所提交材料负责。

### AHICP 文章中的允许用法

把 ICMJE 作为一个具体例子，说明至少有一个有影响力的学术 authorship framework 把作者身份与最终批准及问责联系起来。

### 不得过度主张

**不得**把 ICMJE 描述成所有学科或发布渠道的普遍 authorship law。

**状态：** `EVIDENCE-CONSTRAINT`

**投稿前重新核验：** 是。

## 2. Nature Portfolio / Springer Nature — AI 使用与人类问责

**主要政策入口：** Nature Portfolio Editorial Policies。

https://www.nature.com/nature-portfolio/editorial-policies

**2026-09-17 检查的当前 AI 政策示例：**

- Nature Portfolio 期刊 AI 政策页面，包括 Scientific Reports 的 AI policy；
- Nature Methods editorial，*Using AI responsibly in scientific publishing* (2026)，DOI: 10.1038/s41592-026-03020-1。

### 已核验主张

当前 Nature Portfolio 政策材料在实质上说明：

- 作者仍对原创性、准确性与完整性负责；
- 在透明性要求适用时，应披露 AI 使用；
- AI 工具不能承担人类作者所需承担的问责；
- 相关角色中的学术/编辑判断仍然属于人类责任；
- 政策会继续变化，因此投稿前应重新核验。

### AHICP 文章中的允许用法

把 Nature Portfolio 作为另一个当前例子，用来说明在人类—AI 辅助学术出版中，人类问责仍然处于中心位置。

### 不得过度主张

不得写成“所有出版商都使用相同 AI 规则”。Nature Portfolio 只是一个主要出版体系的当前政策证据，不是普遍规范。

**状态：** `EVIDENCE-CONSTRAINT`

**投稿前重新核验：** 是。

## 3. CRediT — 贡献角色透明度

**主要来源：** NISO CRediT Contributor Role Taxonomy。

https://credit.niso.org/

**标准：** ANSI/NISO Z39.104-2022，DOI: 10.3789/ansi.niso.z39.104-2022。

**2026-09-17 重新核验。**

### 已核验主张

- CRediT 定义了 **14 类 contributor roles**。
- 其目的之一是以透明、结构化方式表示学术成果中的贡献。
- 它可以补充 authorship 判断，但并不自动决定 authorship status。

### AHICP 文章中的允许用法

使用 CRediT 来区分两个问题：

1. 谁完成了哪些类型的工作；
2. 谁满足某个发布渠道的 authorship/accountability 要求。

**状态：** `EVIDENCE-CONSTRAINT`

# 仍然属于 AHICP 提议、而非外部已确立事实的主张

以下内容不得因为在 AHICP 中重要，就被写成已经由上述文献确立：

- Framework Approval 是 AI 时代作者身份的最佳一般解决方案；
- “responsibility concentration” 是人类责任的正确普遍模型；
- “generation–verification asymmetry” 是既定技术术语；
- “semantic version control” 在 AHICP 意义上已经是成熟学术方法术语；
- 以仓库为中心的工作流能够经验证地减少 semantic drift；
- AHICP 会提升 research integrity；
- AHICP 能在不增加严重错误的情况下减少人类审阅负担；
- 仅靠 human-approved framework 就足以满足任何外部发布渠道的 authorship 要求。

这些属于 AHICP 假说、拟议概念或规范主张，需要进一步论证，并在可能时进行经验测试。

### 可支持的主张
该工作展示了一种将经历记录、较高层反思和动态检索结合起来的 Agent memory 架构，用于使 Agent 的后续行为受到过去经历影响。

### 限定
不得把该工作描述为 project-memory governance、human decision persistence 或 AHICP 的证据。

## 10. MemGPT (Packer et al., 2023) — 有限上下文下的分层记忆管理

**来源：** Packer, C., et al. (2023). *MemGPT: Towards LLMs as Operating Systems*. arXiv:2310.08560.

**核验：** arXiv / UC Berkeley Sky Computing Lab，2026-09-20。

### 可支持的主张
MemGPT 把有限 context window 视为长期交互障碍，并提出类似操作系统虚拟内存的分层 context / memory 管理方法。

### AHICP 中的允许用法
说明 Agent memory 研究已经关注跨 session 的长期记忆、不同存储层与有限上下文之间的调度问题。

### 限定
AHICP 的 project memory 问题不同：即使 Agent 能管理自己的长期记忆，项目仍需要外部权威状态、决策 provenance 与人类治理。

## 12. LongMemEval (Wu et al., 2025) 与 MemBench (Tan et al., 2025) — 长期记忆评价

**来源：**
- Wu, D., et al. (2025). *LongMemEval: Benchmarking Chat Assistants on Long-Term Interactive Memory*. ICLR 2025.
- Tan, H., et al. (2025). *MemBench: Towards More Comprehensive Evaluation on the Memory of LLM-based Agents*. Findings of ACL 2025. DOI: 10.18653/v1/2025.findings-acl.989.

**核验：** ICLR Proceedings / ACL Anthology，2026-09-20。

### 可支持的主张
LongMemEval 评价多 session information extraction、reasoning、temporal reasoning、knowledge updates 与 abstention；MemBench 从不同 memory level、interactive scenario 与 effectiveness / efficiency / capacity 等维度评价 Agent memory。

### AHICP 中的允许用法
这些工作说明长期记忆可以被分解为可测试能力，并为 AHICP 的 proposed evaluation 提供方法学背景。

### 限定
AHICP 不应声称这些 benchmark 已经测试了 decision provenance、project governance、Framework Approval 或 Agent replacement 下的项目连续性。

## 15. AHICP-D030 后新增的证据边界

以下主张现在是**人类确认的 AHICP 论文方向**，但仍不是外部文献已经验证的经验事实：
- project memory 应独立于具体 Agent / model；
- Working Memory 可作为长期项目 continuity layer；
- human decision persistence 应成为 first-class project memory；
- Agent/model substitution 可以作为 AHICP 架构 stress test；
- project-memory architecture 可以减少 semantic drift 或提高长期项目质量；
- proposed evaluation framework 的任何具体效果。

论文可以论证这些主张、把它们与相关研究比较，并提出评估设计；在真实实验完成前不得写出效果性结论。

## 17. Weiser & Morrison (1998) — Project Memory: Information Management for Project Teams

**来源：** Weiser, M., & Morrison, J. (1998). “Project Memory: Information Management for Project Teams.” *Journal of Management Information Systems*, 14(4), 149–166. DOI: 10.1080/07421222.1998.11518189.

### AHICP 中的允许用法

### AHICP 的可区分问题
AHICP 把重点进一步放在长期 AI-assisted inquiry / creation 中的 authoritative state、Agent/model substitution、human decision status、authorization/publication boundary 与 repository-grounded governance。

## 21. 本轮 novelty 定位修正

第二轮学术审阅后，方法论文章必须明确保持以下边界：

1. **AHICP 不首创 organizational memory。**
2. **AHICP 不首创 project memory。**
3. **AHICP 不首创 design rationale / architecture knowledge management / decision provenance。**
4. **AHICP 不首创 Agent long-term memory。**
5. 论文当前可以主张的，是一个需要论证与后续验证的**架构性综合贡献**：把长期 Project Memory 与 LLM Agent 可替换性、repository-backed authoritative state、Working Memory continuity、human decision persistence、evidence/provenance、authorization/publication boundaries、Framework Approval 与 Final Artifact Approval 统一为一个 human-led AI-assisted project governance architecture。

是否构成足够的新颖学术贡献，最终仍需要目标学科的同行评审判断，不应在论文中自我断言“首次”或“唯一”。
