# 从这里开始：一个普通人的探究、创作与 AI 协作指南

> 这是整个 Inquiry Publishing Stack 的**人类第一入口**。  
> 如果你不知道 GitHub、Agent、YAML、Cloudflare 是什么，也可以从这里开始。  
> 你不需要先学工具。先理解：这套体系为什么存在，它怎样帮助你，以及哪些事情始终应该由你决定。

---

## 1. 一分钟了解这套体系

你每天都可能遇到这些事情：

- 想学一个新东西；
- 对一个问题产生好奇；
- 要完成作业、文章、研究、报告或一本书；
- 收集了很多资料，却越来越不知道哪些重要；
- 问了 AI 很多次，但过一段时间以后找不到原来的依据；
- 换了一个 AI，又要从头解释；
- AI 写得很好看，但你不确定它是不是说对了；
- 有些材料暂时不想公开，但以后可能想发布。

这套体系要解决的不是“怎样让 AI 替你思考”。

它要解决的是：

> **怎样让你一直掌握自己的问题、证据、判断、决定和作品，同时让 AI 成为一个可以帮助你、可以被检查、也可以被替换的助手。**

最简单地说：

~~~text
你提出问题、决定方向、判断重要事情
        ↓
AHICP 帮你保持思考过程清楚
        ↓
你的项目保存资料、想法、决定和作品
        ↓
PPF 帮你把作品可靠地整理和发布
Vault Interface 帮你只公开应该公开的信息
Starter 帮你和 AI 正确配置整个系统
~~~

你不需要一次学会所有东西。

## 2. 为什么普通聊天不够

聊天很方便，但长期工作只放在聊天里容易发生几个问题。

### 2.1 你会忘记“为什么”

你可能记得最后的结论，却忘了：

- 当时看过哪些资料；
- 哪些只是猜测；
- 为什么排除了另一种方案；
- 哪个决定是你自己确认的；
- 哪句话其实只是 AI 的建议。

### 2.2 AI 也会“忘记”

不同聊天、不同模型、不同 Agent 可能拥有不同上下文。

如果项目只存在于一次对话中，那么换一个工具，很多事情就要重新解释。

### 2.3 好看的答案不等于可靠的答案

AI 很擅长生成流畅文字。

但流畅并不自动意味着：

- 有证据；
- 没有遗漏；
- 没有把猜测写成事实；
- 符合你的真实意思。

### 2.4 项目越长，混乱越容易累积

一个问题做一天，也许聊天就够了。

一个项目做几个月或几年，就需要有地方保存：

- 当前目标；
- 已确认的事实；
- 重要来源；
- 已批准决定；
- 未解决问题；
- 下一步；
- 不能随便改变的约束。

AHICP 的核心思想，就是把这些重要状态从“临时聊天”变成“长期可以检查的项目状态”。

## 3. 使用以后，你会逐渐形成哪些思维习惯

这套体系真正希望提升的，不只是速度。

它更希望帮助你形成一套可靠的探究习惯。

### 3.1 先问清楚问题，再急着找答案

不是看到 AI 就立刻问：

> “告诉我答案。”

而是先想：

- 我到底想知道什么？
- 为什么这个问题对我重要？
- 什么样的答案才算有用？
- 有哪些限制？

### 3.2 把“事实”和“我的判断”分开

例如：

> “这篇资料说 A。”

和：

> “所以我认为 B。”

不是一回事。

前者可以回到来源核对，后者需要说明推理。

### 3.3 把“我不知道”保留下来

不知道并不失败。

一个可靠项目应该能明确写出：

- 已知；
- 未知；
- 有争议；
- 需要继续核实。

### 3.4 重要决定留下原因

以后你自己、另一位合作者或另一个 AI 都可以知道：

> “我们为什么这样做？”

### 3.5 AI 的建议不是你的承诺

AI 可以提出方案。

但只有当你确认以后，它才成为项目真正采用的决定。

### 3.6 做完一步，要让未来还能继续

一个好的工作状态应该让“未来的你”在几个月以后回来时仍能理解：

- 做到哪里；
- 为什么做到这里；
- 下一步是什么。

## 4. 四个组件分别替你解决什么问题

这四个项目逻辑上彼此独立，但可以组成一套完整工作方式。

### 4.1 AHICP：帮助你保持“思考和决定”的控制权

**AHICP — AI-Assisted Human Inquiry and Creation Protocol**

它处理的问题是：

> 我怎样和 AI 一起思考、研究和创作，同时不把自己的判断交给 AI？

它帮助保存：

- 目标；
- 问题；
- 来源；
- 证据；
- 推理；
- 假设；
- 决定；
- 人类批准；
- 当前工作状态；
- 交接信息。

因此，AHICP 是整个体系的**人类方法中心**。

[AHICP 主页](https://chongliuphil.github.io/AI-Assisted-Human-Inquiry-and-Creation-Protocol/)

### 4.2 PPF：帮助你的作品长期保存、构建和发布

**PPF — Personal Publishing Framework**

它处理的问题是：

> 我的文章、研究、书、课程或知识项目怎样不依赖某一个网站，并且以后还能重新构建和发布？

它关心：

- canonical source；
- 网页输出；
- 书籍/文档输出；
- 构建过程；
- 发布状态；
- 版本；
- Continuous Web；
- 可重建性。

[PPF 主页](https://chongliuphil.github.io/Personal-Publishing-Framework/)

### 4.3 Vault Interface：帮助你只公开应该公开的信息

它处理的问题是：

> 怎样让一个项目在公共体系中被理解，而不必公开私人材料？

它提供公共 metadata contract。

例如，一个项目可以公开：

- 名称；
- 简介；
- 公开网站；
- 发布状态；

但不必公开：

- 私人研究记录；
- 工作记忆；
- 未发布手稿；
- 密码；
- private repository 的 locator。

[Vault Interface 主页](https://chongliuphil.github.io/Vault-interface/)

### 4.4 Starter：帮助你把这些东西正确组合起来

Starter 处理的问题是：

> 我不想自己研究所有配置，能不能让 AI 按正确规则替我建立项目？

它负责：

- 组合；
- profile；
- adoption；
- upgrade；
- machine-readable state；
- Agent 配置入口。

对一个完整新项目，当前默认基线是：

~~~text
完整 AHICP
+ 完整 PPF
+ Vault Interface
+ 项目自己的内容
~~~

[Starter 主页](https://chongliuphil.github.io/Inquiry-Publishing-Project-Starter/)

## 5. 使用前后有什么不同

### 只使用临时聊天

~~~text
想到问题
→ 问 AI
→ 得到答案
→ 再问
→ 再复制一段文字
→ 几周以后找不到依据
→ 不知道哪些已经确认
→ 换 AI 后重新解释
~~~

### 使用这套体系

~~~text
提出问题
→ 保存目标
→ 收集并保留来源
→ AI 帮助整理和分析
→ 区分事实 / 推断 / 建议
→ 人确认重要决定
→ 保存当前工作状态
→ 形成作品
→ 按授权发布
→ 下一位人类或 AI 可以继续
~~~

区别不是“文件变多了”。

区别是：

> **项目不再依赖某一次聊天的记忆。**

## 6. AI 可以替你做什么，不能替你做什么

### AI 很适合帮助

- 搜索和整理资料；
- 比较观点；
- 建立表格；
- 总结长文；
- 找出矛盾；
- 提出结构；
- 草拟文本；
- 检查引用；
- 重复性文件维护；
- 构建网页；
- 根据已经批准的规则执行技术步骤；
- 为下一位协作者整理交接。

### 人应该保留的责任

- 为什么做这个项目；
- 什么问题值得问；
- 什么价值最重要；
- 是否接受一个重要解释；
- 是否采用某个关键方案；
- 哪些私人材料可以公开；
- 是否正式发布；
- 对最终内容承担什么责任。

一句话：

> **AI 可以扩大你的能力，但不应该替你成为项目的主人。**

## 7. 三个非常简单的例子

### 例子一：学生做一个关于恐龙的小项目

没有这套体系时：

- 问几个 AI；
- 复制答案；
- 不知道信息来自哪里；
- 最后很难解释为什么相信它。

使用以后：

1. 写下问题：“为什么恐龙会灭绝？”
2. 保存几份可靠资料。
3. 让 AI 分别整理“已知证据”和“仍有争议的解释”。
4. 自己决定报告重点。
5. 保存来源。
6. 完成作品。
7. 如果公开网页，只发布最终内容，不公开私人草稿。

即使学生不知道 Git 是什么，AI Agent 也可以帮助维护这些结构。

### 例子二：一个人长期学习一个主题

例如学习经济学、历史、编程、哲学或语言。

半年以后，最困难的往往不是“找不到新信息”，而是：

- 不记得已经学过什么；
- 不知道哪些问题仍没有解决；
- 新 AI 不知道以前的学习路线。

AHICP 可以保存学习路线、来源、理解变化和当前问题。

### 例子三：写一本书或完成长期研究

此时四个组件都会发挥作用：

~~~text
AHICP
→ 保存研究目的、论证、证据和决定

PPF
→ 管理 manuscript、build 和 publication

Vault Interface
→ 公开安全的项目 metadata

Starter
→ 让 Agent 正确组合并升级这些组件
~~~

## 8. 隐私和公开不是一回事

这是整个体系非常重要的一条原则。

你可以：

~~~text
GitHub source repository = private
Web publication = restricted
~~~

也可以以后变成：

~~~text
GitHub source repository = private
Web publication = public
~~~

因此：

> **公开最终作品，不代表必须公开你的全部研究过程。**

原创、未发布或私人材料默认留在 private source。

只有经过批准的内容才进入公开输出。

密码、token、private key 等秘密永远不应该进入仓库。

## 9. 如果我完全不懂技术怎么办

没有关系。

你不需要先学：

- Git；
- GitHub branch；
- YAML；
- CI；
- Cloudflare；
- API；
- command line。

你可以从一句普通语言开始：

> “我想做一个长期项目。请按照 AHICP / Inquiry Publishing Stack 帮我建立它。尽量替我完成技术配置，只在需要我判断、批准、登录或输入秘密时告诉我，并一步一步说明。”

一个遵守本体系的 Agent 应该：

1. 理解你的项目是什么；
2. 默认采用完整 AHICP + PPF + Vault Interface；
3. 默认保护原创和未发布材料；
4. 建立必要文件；
5. 运行检查；
6. 能自动做的技术步骤尽量自动做；
7. 真正需要你操作时给出明确步骤；
8. 不要求你把秘密粘贴给 AI；
9. 完成后告诉你现在处于什么状态。

如果 Agent 不能直接操作浏览器，可以把需要操作网页的步骤交给 browser-capable Agent / Work 模式。

## 10. 第一次使用：只做五件事

### 第一步：告诉 AI 你想做什么

不需要专业术语。

例如：

> “我想长期研究城市交通，并最后写成一篇文章。”

### 第二步：告诉 AI 什么不能擅自决定

例如：

> “公开发布之前必须先问我。”

### 第三步：让 Agent 按完整体系建立项目

可以使用：

> “按照 Inquiry Publishing Stack 的默认完整配置建立这个项目。保留我的目标、来源、决定和工作状态；原创内容默认 private。”

### 第四步：开始正常工作

之后你仍然可以像普通聊天一样说：

- “帮我找资料。”
- “比较这两种解释。”
- “这里我没看懂。”
- “把我刚才的决定记录下来。”
- “下一步应该做什么？”

### 第五步：让项目自己记住状态

结束一次重要工作时，可以说：

> “请把已经确认的决定、未解决问题和下一步写回项目状态，让下一位 AI 能继续。”

## 11. 你可以逐渐学习，而不是一次学完

### Level 0 — 只会聊天

你只表达目标。

AI 帮你维护结构。

### Level 1 — 会看项目状态

你开始知道：

- 当前目标在哪里；
- 来源在哪里；
- 哪些决定已经批准。

### Level 2 — 会检查来源与变化

你可以查看：

- 为什么作出一个决定；
- 哪个文件发生变化；
- AI 是否遵守规则。

### Level 3 — 会控制发布

你理解：

- private source；
- restricted Web；
- public release；
- publication authorization。

### Level 4 — 会管理复杂项目

这时 Git、CI、Cloudflare、Agent routing 等技术细节才真正值得深入学习。

这套体系的目标不是逼每个人变成工程师。

目标是：

> **技术复杂性尽量由系统和 Agent 承担，而关键判断仍然留给人。**

## 12. 两个入口：给人和给机器

为了避免混乱，整个体系有两个不同的第一入口。

### 人类第一入口：AHICP

如果你想知道：

- 为什么需要这套体系；
- 它怎样帮助思考；
- 它对普通人意味着什么；
- 四个组件为什么存在；

从本指南和 AHICP 主页开始。

### AI / 配置第一入口：Starter

如果 Agent 要：

- 建立项目；
- 恢复四个组件；
- 配置 profile；
- 升级；
- 部署；

它应该进入 Starter 的 machine-readable ecosystem 和 Agent Retrieval Contract。

因此：

~~~text
Human conceptual entry
        ↓
      AHICP

Machine/configuration entry
        ↓
      Starter
~~~

两者互相连接，但责任不同。

## 13. 这套体系不承诺什么

它不能保证：

- AI 永远正确；
- 所有来源都可靠；
- 所有项目都成功；
- 记录越多就一定越聪明；
- 使用流程就能替代真正学习；
- 自动化可以替代人的责任。

它提供的是一种更容易发现错误、保存依据、继续工作和明确责任的结构。

---

## 14. 最值得记住的十句话

1. **问题属于你，不属于 AI。**
2. **AI 的建议不是你的决定。**
3. **事实、推断和意见要分开。**
4. **重要来源要能回去检查。**
5. **重要决定要保存为什么。**
6. **不知道的事情可以明确写“不知道”。**
7. **聊天可以临时，项目状态要持久。**
8. **工具可以替换，人的目的不能丢。**
9. **公开作品不等于公开全部私人过程。**
10. **让 AI 承担技术复杂性，让人保留关键判断。**

## 最后的核心原则

工具、模型、平台都会变化。

一个长期项目真正需要持续存在的是：

- 人的目的；
- 可检查的依据；
- 清楚的决定；
- 可以继续的工作状态；
- 对隐私和公开的控制；
- 人对最终结果的责任。

这就是 AHICP 以及整个 Inquiry Publishing Stack 想保护的东西。
