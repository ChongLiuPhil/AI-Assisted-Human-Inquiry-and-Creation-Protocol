# HARC 双语同步规范

**状态：规范性项目规则**  
**中文：权威基准（canonical）**  
**英文：同步镜像**

## 1. 基本规则

HARC 项目的实质性文本采用中英双语维护。

- 中文版本是语义、编辑和人类审阅的权威基准。
- 英文版本是中文版本的同步翻译镜像。
- 任何实质性修改必须在同一工作轮次中同步更新两种语言。
- 如果中英文发生实质冲突，以中文为准，并立即修复英文版本。
- 仅更新其中一种语言，不视为一次完整修改。

## 2. 文件命名

推荐：

- 中文规范版本：`NAME.zh-CN.md`
- 英文镜像：为了兼容既有 GitHub 默认路径可继续使用 `NAME.md`；否则使用 `NAME.en.md`

根目录 `README.md` 可继续作为 GitHub 默认英文入口，但 `README.zh-CN.md` 是该文档的中文规范基准。

## 3. 哪些文件必须双语

所有承载人类可读语义的实质性 Markdown 文档都应有中英文对应版本，包括：

- 协议规范与治理规则；
- Content / Form / Protocol Core；
- 决策日志；
- Argument Map 与 Framework Status；
- 审计文件；
- Evidence / source notes；
- 方法论文章、白皮书和说明文档；
- 可复用项目模板与形式配置模板；
- CONTRIBUTING、ROADMAP、许可决策说明等项目治理文档。

## 4. 可以保持单份的技术文件

下列文件在内容本身语言中立时可以保持单份：

- BibTeX 数据；
- JSON / YAML schema；
- 程序代码；
- 原始数据；
- 机器生成的哈希或状态清单。

但解释这些技术文件的说明文档仍应双语。

## 5. 同步完成条件

一次双语编辑只有在以下条件同时满足时才算完成：

1. 中文规范版本已经更新；
2. 英文镜像已经同步；
3. 两个版本的主张、要求、状态、未决问题和链接关系在语义上等价；
4. 没有一方新增而另一方遗漏的实质性段落；
5. 如修改影响 Decision Log、Framework Status 或其他上游状态，两种语言也都已同步。

## 6. Agent 行为

AI Agent 应先编辑中文规范版本，再生成或更新英文镜像。

如果 Agent 发现旧项目中只有单语文件，应把它视为一个同步缺陷，并补齐对应语言版本。

Agent 不得因为英文版本文字更成熟而反向改变中文含义；如认为中文需要修改，应回到中文规范版本先完成内容决策。

## 7. 新项目继承

使用 HARC 创建新项目时，可以显式选择双语配置。若选择本项目的默认双语配置，则初始化时就应同时创建中文 canonical 与英文 mirror，而不是在项目后期补翻译。


## 8. 规则切换前的历史追赶

中文 canonical / 英文 synchronized mirror 规则自 2026-09-18 起成为 HARC 的正式治理规则。

对于该规则建立之前已经存在的双语文件，若历史上**英文版本实际上包含比中文版更新的实质性发展**，不得为了形式上立即“以中文为准”而删除这些较新内容。

应执行一次性的历史追赶：

`pre-cutover English development -> Chinese catch-up -> bilingual parity -> Chinese canonical cutover`

具体要求：

1. 识别规则建立前英文版中、中文版尚未吸收的实质性内容；
2. 将这些内容纳入中文版，使中文达到切换时真正的最新语义状态；
3. 再把英文整理成该最新中文版的同步镜像；
4. 完成 parity check 后，才视为 canonical cutover 完成；
5. 切换完成后，不再允许英文独立发展。

这一历史追赶是迁移例外，不改变长期治理方向。

## 9. 切换后的正常编辑方向

canonical cutover 完成后，所有正常实质性修改必须遵循：

`Human decision -> Chinese canonical -> English synchronized mirror`

英文版本可以在翻译层面改善表达，但不得独立新增、删除、强化或弱化实质内容。

如果英文表达暴露出中文内容需要修改，应先回到中文 canonical 完成内容修改，再同步英文，而不能直接让英文成为新的实质性来源。
